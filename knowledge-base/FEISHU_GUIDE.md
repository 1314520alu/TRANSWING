# 飞书知识库上传指南（Transwing）

本机已安装飞书客户端：

```text
路径：C:\Users\alu\AppData\Local\Feishu\Feishu.exe
版本：约 7.70.x（User Data 在 AppData\Local\Feishu）
```

**重要**：本地飞书只是客户端；**分类目录在 Wiki 里手动建，向量化在飞书云端自动完成**，本地没有向量库文件。

---

## 三种能力对比

| 产品 | 上传 | 自动分类 | 向量化 | 适合 |
|------|------|---------|--------|------|
| **知识问答** | 拖本地 PDF/Word/PPT/上传 | 弱（进「知识问答」文件夹） | ✅ 自动 | 个人/小团队快速试用 |
| **Wiki 知识库** | 导入文档、粘贴 md | ✅ **手动建目录** | 需被知识问答/Aily 引用后才 AI 检索 | 队友协作阅读 |
| **Aily 智能伙伴** | 本地 txt、云文档、Wiki 节点 | 按知识库/标签配置 | ✅ 自动分段+向量 | 企业、可调校切片 |

飞书 **没有**「上传后 AI 自动帮你分到固件/SITL 文件夹」的完整能力；**分类要靠 Wiki 目录结构**（我们已用脚本按 `index.yaml` 分好文件夹）。

## 推荐流程（Transwing）

### 第 0 步：生成分类导出包

在仓库根目录：

```bash
python tools/prepare_feishu_kb.py --open
```

输出：`outputs/feishu-kb-export/`

```text
outputs/feishu-kb-export/
├── 00_上传说明.txt
├── manifest.json
├── airframe_机体与建模/
├── firmware_固件与参数/
├── sitl_lua_SITL与Lua/
├── guard_模式转换与守卫/
└── design_设计与计划/
```

md/csv/params 已转为 `.txt`，便于飞书本地上传。

---

### 方式 A：知识问答（最快，自动向量化）

1. 打开 **Feishu.exe**
2. 左侧导航 → **知识问答**（或置顶入口；也可浏览器 <https://ask.feishu.cn/>）
3. 点击 **上传** 或对话输入框旁的 **+**
4. 从 `outputs/feishu-kb-export/` **按子文件夹分批**选择 `.txt` 文件上传
5. 等待右下角「解析完成」（约几十秒/文件）
6. 在对话 **··· → 知识范围 → 指定本次范围**，勾选刚上传的资料
7. 提问测试，例如：`TW_BLEND_AS 是多少？`

**向量化**：上传解析完成后，飞书云端自动 **切片 + 向量索引**，无需额外设置。

**局限**：

- 试用版可能 **只能搜你上传的文件**，不含企业其他文档
- 消耗 **AI 额度**（企业知识问答约 20 点/次有效回答）
- 分类弱：文件会进「知识问答」相关空间，不如 Wiki 清晰

---

### 方式 B：Wiki 知识库 + 知识问答（推荐团队）

**1. 建库并手动分类（对应我们的 index.yaml）**

1. 飞书 → **云文档** → 左侧 **知识库** → **新建知识库**
2. 名称：`Transwing 研发知识库`
3. 在 Wiki 左侧目录 **手动创建节点**（与导出文件夹一致）：

   ```text
   01 机体与建模
   02 固件与参数
   03 SITL与Lua
   04 模式转换与守卫
   05 设计与计划
   ```

4. 各节点下：**+ → 文档** → 将对应 `.txt` 内容粘贴，或用 Word 导入

**2. 让 AI 能向量检索 Wiki**

1. 打开 **知识问答**
2. **··· → 知识范围 → 指定本次范围**
3. 选择 **Transwing 研发知识库** 或指定子节点
4. 提问时 AI 会从 Wiki 内容 **检索 + 向量化召回**（企业完整版）

**3. 邀请队友**

Wiki → 左下 **设置** → **成员设置** → 添加成员

---

### 方式 C：Aily 智能伙伴（企业，可控制切片）

适合需要 **预览切片、调召回、挂 Bot** 的团队。

1. 进入 **飞书 Aily**（智能伙伴创建平台，需企业权限）
2. **数据与知识 → 知识库 → 添加**
3. 数据源可选：
   - **飞书知识库** / 云文档 / 子节点（推荐：先建 Wiki 再关联）
   - **本地文件**：上传 `outputs/feishu-kb-export/` 下 `.txt`
4. **分段方式** → 选 **自动分段**（默认 `\n\n`、`\n` 等，单段 <800 tokens）
5. 保存后系统自动 **向量化**；可在界面 **预览切片**
6. 创建 **知识问答技能**，关联该知识库 → 发布给团队

Aily 文档：[数据预处理](https://www.feishu.cn/content/adcbsjqc)

## 「自动分类」实际是什么意思

| 你说的 | 飞书实际行为 |
|--------|-------------|
| 自动分类 | **Wiki 目录需自己建**；我们用 `prepare_feishu_kb.py` 在导出时已按类分文件夹 |
| 自动向量化 | ✅ 上传/关联知识源后 **云端自动** 切片+embedding |
| AI 自动打标签 | 主要在 **Aily 结构化数据 / AI 字段**，不是普通 Wiki 默认功能 |

---

## 从 Git 持续同步

飞书 **不会** 自动 watch GitHub。更新流程：

```text
改 Git 文档 → python tools/prepare_feishu_kb.py → 重新上传或更新 Wiki 页面
```

长期建议：**Git 为源，飞书为只读视图**；或在企业版用 **开放平台 API** 写同步脚本（需自建应用）。

## 费用提醒

|------|---------|
| Wiki 存文档、队友协作 | 基础版通常够用 |

| 知识问答 API | 多需 AI 企业/旗舰版 |
| Aily | 企业功能，视租户版本 |

## 和 Cursor 的关系

- Cursor **默认不能**读飞书 Wiki
- 精确参数仍以 **Git + search_kb.py** 为准
- 若要让 Cursor 调飞书：需 **飞书开放平台 MCP/API**（另配）
